# Specification Freeze

**Purpose:** Freeze PRD, TRD, UI/UX, schema, API contracts, security model, project map, and acceptance criteria before implementation starts.

## When to use this skill
Use once discovery is complete, before the first implementation task begins.

## Steps
1. Confirm every required spec section is filled in, not left as an empty template heading.
2. Mark the specs as frozen and record the freeze date/decision in `docs/DECISION_LOG.md`.
3. After this point, route any new requirement through `change-management`, not directly into a task.

## Evidence required
Filled-in spec documents plus a freeze entry in `docs/DECISION_LOG.md`.

Do not mark work that uses this skill as complete without the evidence above. See `docs/EVIDENCE_STANDARDS.md` for the general evidence rules.
