# Discovery First

**Purpose:** Never write implementation code before project identity, discovery, follow-up questions, specifications, and freeze are complete.

## When to use this skill
Use at the very start of a new project or when asked to begin building before requirements exist.

## Steps
1. Ask for the project name and save it in `docs/PROJECT_INTAKE.md` before anything else.
2. Work through `docs/DISCOVERY_QUESTIONNAIRE.md`, asking follow-up questions until no material ambiguity remains.
3. Draft PRD/TRD/UI-UX/schema/API/security specs, then freeze them before the first implementation task begins.

## Evidence required
Completed `docs/PROJECT_INTAKE.md` and answered `docs/DISCOVERY_QUESTIONNAIRE.md`, with `docs/memory/PROJECT_STATE.md` showing phase progressed past INTAKE.

Do not mark work that uses this skill as complete without the evidence above. See `docs/EVIDENCE_STANDARDS.md` for the general evidence rules.
